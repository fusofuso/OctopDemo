# 本地启动指南

本文档说明如何在本机从源码启动 Octop（后端 API + Web 控制台），用于日常开发与调试。

## 1. 前置条件

| 依赖 | 版本 | 说明 |
|------|------|------|
| Python | 3.12+ | 由 `uv` 管理，无需手动安装 |
| uv | 最新版 | `uv sync` / `uv run` 的唯一入口 |
| Node.js | 18+（推荐 20/22） | 仅在需要构建或调试前端时使用 |
| npm | 随 Node 附带 | 前端依赖安装 |

```bash
python3 --version   # 参考用；实际由 uv 拉取 3.12
uv --version
node --version
```

> Octop 的运行数据统一存放在 `~/.octop/`，源码项目使用独立的 `.venv/`，二者互不影响。

## 2. 安装依赖

在仓库根目录执行：

```bash
uv sync
```

该命令会：

- 在仓库根创建 `.venv/`（Python 3.12）；
- 以 editable 模式安装本地 `octop` 源码；
- 从 PyPI 安装 `octop-harness` / `octop-gateway` / `octop-memory` / `octop-browser` 及开发依赖（`pytest`、`ruff`、`mypy` 等）。

验证入口可用：

```bash
uv run octop --version
```

> 若 `uv.lock` 中依赖指向本地路径且不可用，可改用 `make install-online`，它会创建 `.venv-online` 并从 PyPI 拉取 harness 组件，随后用 `make run-online` / `make test-online` 操作。

## 3. 首次初始化

全新环境需要初始化 `~/.octop/`（建库、写配置、创建首个管理员）：

```bash
# 交互式向导
uv run octop init

# 或非交互，直接指定管理员账号
uv run octop init --yes --admin-username admin --admin-password octop1234
```

密码策略：至少 8 位，且同时包含字母和数字。

若 `~/.octop/` 已存在且非空，`init` 会拒绝执行；此时说明环境已初始化，直接跳到下一步即可（如需重建，加 `--force`，会清空全部数据）。

**隔离开发数据目录**（推荐，避免污染正式数据）：

```bash
export OCTOP_HOME="$PWD/.octop-dev"
uv run octop init --yes --admin-username admin --admin-password octop1234
```

`OCTOP_HOME` 决定数据根目录，取消该变量即回到 `~/.octop`。

## 4. 启动服务

### 4.1 仅后端（前台）

```bash
uv run octop run
```

按 `Ctrl-C` 停止。默认监听 `http://127.0.0.1:8088`。

指定地址与端口（会写回 `config.json`）：

```bash
uv run octop run --host 0.0.0.0 --port 9000
```

开发时开启自动重载（代码改动后自动重启）：

```bash
uv run octop run --reload
```

### 4.2 前端

后端只提供已构建的 SPA 产物，位于 `src/octop/dashboard/`。有两种方式：

**方式 A：构建产物由后端直接服务（推荐，单端口 8088）**

```bash
make build-frontend      # = cd dashboard && npm ci && npm run build
uv run octop run
```

> 关键顺序：`build_app` 在启动时检查 `src/octop/dashboard/index.html`。若构建产物是启动之后才生成的，需重启后端才会注册 SPA 路由。

**方式 B：Vite 开发服务器（热更新，双端口）**

```bash
# 终端 1：后端
uv run octop run

# 终端 2：前端（Vite :5173，/api 反向代理到 8088）
make dev-frontend
```

访问 `http://127.0.0.1:5173`。Vite 已配置把 `/api` 与 WebSocket 代理到后端。

### 4.3 前后端一条命令

```bash
make dev        # 同时启动 Vite dev server 与 octop run
```

### 4.4 后台启动（脚本 / 无人值守）

```bash
mkdir -p /tmp/octop-dev
setsid nohup uv run octop run > /tmp/octop-dev/octop.log 2>&1 < /dev/null &
```

停止进程：

```bash
pkill -f "octop run"
```

## 5. 验证

```bash
# 健康检查：ok=true、db=true、用户与运行中 Agent 数量
curl -s http://127.0.0.1:8088/api/health

# 初始化状态：setup_required=false 表示已初始化
curl -s http://127.0.0.1:8088/api/setup/status

# SPA 首页（期望 200 与 <title>Octop</title>）
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8088/
```

浏览器打开 `http://127.0.0.1:8088`，使用 `octop init` 时设置的管理员账号登录。

交互式 API 文档默认关闭，在 `~/.octop/config.json` 中设置 `"enable_api_docs": true` 后重启，访问 `http://127.0.0.1:8088/api/docs`。

## 6. 配置与数据

| 路径 | 内容 |
|------|------|
| `~/.octop/config.json` | 绑定地址、端口、数据库、TLS、插件开关等 |
| `~/.octop/octop.db` | 控制面数据库（SQLite，WAL） |
| `~/.octop/agents/<id>/` | 各 Agent 工作区 |
| `~/.octop/logs/` | 运行日志 |

端口优先级：CLI 参数 > `OCTOP_BIND_HOST` / `OCTOP_PORT` 环境变量 > `config.json` > 默认值。

常用 CLI：

```bash
uv run octop models          # 供应商与模型
uv run octop agent list
uv run octop channel list
uv run octop cron list
```

## 7. 质量检查

```bash
make all              # format-all + lint + typecheck + test（发布门槛）
make test             # pytest -m "not live"
make typecheck        # mypy --strict
cd dashboard && npx tsc -b    # 前端类型检查
```

## 8. 常见问题

**端口被占用**：`ss -ltnp | grep 8088` 查占用，改用 `uv run octop run --port 9000`。

**`/` 返回 404**：前端产物缺失或未重启。执行 `make build-frontend` 后重启后端。

**`init` 报 “already exists and is not empty”**：环境已初始化，无需重复 init；如需重来用 `--force`（会清空数据）。

**`uv sync` 拉取依赖失败**：检查网络 / 镜像配置；或改用 `make install-online`。

**改动前端后页面未更新**：方式 A 需重新 `make build-frontend` 并重启后端；方式 B 由 Vite 热更新。
