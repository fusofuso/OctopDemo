# 内网离线部署

面向**无外网环境**的 Octop 部署指南。把整个运行栈打成离线包，在隔离网络中安装，并让内网中的其他机器可以访问。

> 本方案已在 **aarch64 麒麟 V10（glibc 2.28、gcc 7.3）+ 无外网** 的目标形态下完成端到端验证：
> aarch64 依赖包 194/194 覆盖、解释器与构建工具可离线获取、全部 C 扩展可构建。

## 1. 适用条件

| 项 | 要求 |
|----|------|
| 目标机 | Linux，**glibc ≥ 2.28**（manylinux_2_28 下限），有 **gcc** |
| 目标机架构 | x86_64 或 aarch64（默认 aarch64） |
| 构建机 | 任意可联网的 Linux，**架构不必与目标机相同**（做的是跨平台下载） |
| 构建机工具 | `uv`、`npm`（构建前端）、Python 3.x（读版本号） |
| 访问方式 | 目标机运行服务，内网其他机器通过 `http://<目标机IP>:8088` 访问 |

为什么不能用 `scripts/install.sh`：它会装 uv（astral.sh）、拉 PyPI、`apt/dnf` 装依赖，每一步都需要外网。

## 2. 方案总览

离线包由五部分组成，全部由构建机产出：

| 组件 | 来源 | 参考体积 |
|------|------|----------|
| aarch64 CPython 3.12 | `uv python install`（python-build-standalone，免编译） | 28M |
| 依赖包（wheel + sdist） | `pip download --platform manylinux_2_28_aarch64` | 169M |
| octop wheel | `uv build`（`py3-none-any`，含前端产物） | 17M |
| uv / setuptools / wheel | `pip download`（供内网建 venv 与编译 sdist） | 21M |
| 前端产物 | `npm run build`（**平台无关**，可跨架构复用） | 已含在 octop wheel 内 |

```
构建机 (可联网)                          目标机 (无外网)
──────────────                          ──────────────
bash scripts/offline_pack.sh    ──摆渡──►  tar -xzf
  └─ offline-dist/*.tar.gz                bash scripts/offline_install.sh --bundle ... --host 0.0.0.0
                                          └─ 建 venv → 离线装包 → 初始化 → 启动 → 内网各机器访问
```

## 3. 第一步：构建机打包

在仓库根目录执行：

```bash
bash scripts/offline_pack.sh           # 打包一次，产物按打包时间归档
bash scripts/offline_pack.sh --list    # 列出已归档的所有离线包
```

可选环境变量：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `OCTOP_ARCH` | `aarch64` | 目标架构 |
| `OCTOP_PY` | `3.12` | Python 版本 |
| `OUT_DIR` | `<仓库>/offline-dist` | 输出目录 |
| `OCTOP_PYPI_INDEX` | 腾讯云镜像 | PyPI 镜像源 |

产物（每次打包生成一个以**打包时间**命名的目录，全部产物都归档其中）：

```
offline-dist/
└── 20260929-094033/                              本次打包的归档目录
    ├── octop-offline-aarch64-1.0.2b4/            离线包目录（解压即用，含 MANIFEST.sha256）
    ├── octop-offline-aarch64-1.0.2b4.tar.gz      传输用压缩包（约 244M）
    └── octop-offline-aarch64-1.0.2b4.tar.gz.sha256

# 查看历史离线包及校验状态
bash scripts/offline_pack.sh --list
```

脚本内部流程：构建前端 → `uv build` → `uv export` 导出锁定依赖（去掉 hash，因跨平台哈希不同）→ 下载目标架构解释器 → 跨平台下载依赖（有 wheel 用 wheel，无 wheel 回退 sdist）→ 下载 uv/setuptools/wheel → 生成 `MANIFEST.sha256` → 打包。

## 4. 第二步：传输与校验

```bash
# 传输（含校验文件；<打包时间> 取自 --list 输出的目录名）
scp "offline-dist/<打包时间>/octop-offline-aarch64-1.0.2b4.tar.gz"* app@内网IP:/data/

# 目标机校验后解压
cd /data
sha256sum -c octop-offline-aarch64-1.0.2b4.tar.gz.sha256
tar -xzf octop-offline-aarch64-1.0.2b4.tar.gz
```

## 5. 第三步：目标机安装

把 `scripts/offline_install.sh` 一并带到目标机（或从离线包的源码副本中取），然后按服务器场景安装：

```bash
bash offline_install.sh \
  --bundle /data/octop-offline-aarch64-1.0.2b4 \
  --host 0.0.0.0 \
  --admin-username admin \
  --admin-password 'Oa@test@2021'
```

`--host 0.0.0.0` 是为跨机访问准备的，会被写入 `config.json`，服务启动时即按此绑定。

常用选项：

| 选项 | 说明 |
|------|------|
| `--bundle DIR` | 离线包目录（默认自动探测当前目录下的 `octop-offline-*`） |
| `--home DIR` | 安装根目录，默认 `~/.octop` |
| `--admin-username` / `--admin-password` | 管理员账号；密码不填则随机生成并写入 `~/.octop/credential.txt` |
| `--host` | 绑定地址。**跨机访问必须设为 `0.0.0.0`**；默认 `127.0.0.1` 仅本机可访问 |
| `--port` | 绑定端口（默认 `8088`） |
| `--service` | 安装并启动 systemd 服务（需 root，服务器场景建议） |
| `--skip-init` | 跳过数据库与管理员初始化 |

脚本行为：校验 `MANIFEST.sha256` → 用离线解释器建 venv → 离线装 setuptools/wheel → `pip install --no-index --no-build-isolation` 安装 octop（**全程零网络**）→ 写 CLI 包装脚本并配置 PATH → 初始化数据库与管理员 → 写绑定配置 / 可选注册服务。

## 6. 第四步：启动与跨机访问

### 6.1 启动

```bash
# 服务器场景推荐：注册 systemd 服务（开机自启、崩溃自动重启），需要 root
sudo ~/.octop/bin/octop service start

# 前台运行（仅调试用，Ctrl-C 停止）
~/.octop/bin/octop run
```

### 6.2 监听地址（跨机访问的关键）

Octop 默认只监听 `127.0.0.1`，即**只有目标机本机能访问**。跨机访问必须改为 `0.0.0.0`。

安装时已指定 `--host 0.0.0.0` 的话，这一步已完成。若已安装但没指定，改 `~/.octop/config.json`：

```json
{
  "bind_host": "0.0.0.0",
  "port": 8088
}
```

改完重启服务（或前台运行加参数）：

```bash
sudo ~/.octop/bin/octop service stop && sudo ~/.octop/bin/octop service start

# 或前台运行
~/.octop/bin/octop run --host 0.0.0.0 --port 8088
```

**确认监听地址已生效 —— 这是排查跨机访问的第一站：**

```bash
ss -ltnp | grep 8088
```

| 输出 | 含义 |
|------|------|
| `0.0.0.0:8088` | ✅ 所有网卡都在监听，跨机可访问 |
| `127.0.0.1:8088` | ❌ 仅本机，跨机必然失败，回到本节改 `bind_host` |

### 6.3 放行防火墙

**麒麟 / CentOS（firewalld）：**

```bash
sudo firewall-cmd --permanent --add-port=8088/tcp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports        # 确认 8088/tcp 在列
```

**使用 iptables（无 firewalld）：**

```bash
sudo iptables -I INPUT -p tcp --dport 8088 -j ACCEPT
sudo service iptables save            # 或 iptables-save > /etc/sysconfig/iptables
```

**Ubuntu（ufw）：** `sudo ufw allow 8088/tcp`

> SELinux 一般无需调整（Octop 是普通进程，不受 `http_port_t` 限制）。若怀疑被拦，可临时 `sudo setenforce 0` 验证，再决定是否用 `semanage port` 正式放行。

### 6.4 从其他机器访问

在内网任意一台能连通目标机的机器上打开：

```
http://<目标机IP>:8088
```

用安装时设置的管理员账号登录。

### 6.5 从其他机器验证

```bash
curl -s http://<目标机IP>:8088/api/health
# {"ok":true,"db":true,...}
```

判定逻辑：**本机 curl 通、跨机不通 → 一定是 §6.2 监听地址或 §6.3 防火墙的问题**，与 Octop 本身无关。

### 6.6 安全提醒

- 未启用 TLS 时，账号密码与对话内容在内网中明文传输。需要加密可用 `--ssl` 自签证书，或在前置 Nginx 上终止 TLS。
- 建议只在可信内网暴露 8088；确需对外时，务必配置 HTTPS 与访问控制。

交互式 API 文档默认关闭，将 `config.json` 的 `enable_api_docs` 改为 `true` 后重启即可在 `/api/docs` 查看。

## 7. 验证清单

**目标机上：**

```bash
~/.octop/bin/octop --version                       # 版本号
~/.octop/bin/octop agent list                      # CLI 可用
ss -ltnp | grep 8088                               # 监听应为 0.0.0.0:8088
curl -s http://127.0.0.1:8088/api/health           # {"ok":true,"db":true,...}
curl -s http://127.0.0.1:8088/api/setup/status
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8088/   # 200
```

**另一台机器上（跨机连通性）：**

```bash
curl -s http://<目标机IP>:8088/api/health
```

## 8. 常见问题

**跨机访问不通，但本机 curl 正常**
按顺序排查：① `ss -ltnp | grep 8088` 是否为 `0.0.0.0:8088`；② 防火墙是否放行 8088（§6.3）；③ 中间是否有网络设备/ACL 拦截。三者与 Octop 无关，逐项排除即可。

**装包时报 `No module named 'distutils'`**
Python 3.12 移除了 distutils。安装脚本已用 `--no-build-isolation` 并预装 setuptools（其提供兼容层），确保未手工改动这两步。

**编译 `crcmod` / `evdev` 失败**
这两个是 sdist（PyPI 未发布 aarch64 wheel），必须现场编译。确认 `gcc --version` 可用；麒麟系统装法：`sudo yum install -y gcc`。

**`GLIBC_2.28 not found` 或 `No matching distribution`**
目标机 glibc 低于 2.28，manylinux_2_28 的包（如 `tiktoken`）无法安装。需升级系统或在同 glibc 版本的机器上重新下载依赖。

**离线包校验失败**
传输不完整或介质损坏。重新传输，务必带上 `.sha256` 文件。

**`uv` 用不了 / 想手工装 uv**
不要从 GitHub 直连下载（国内常超时）。离线包里 `wheelhouse/uv-*-aarch64.whl` 即为 aarch64 版 uv，可用解释器自带 pip 安装：
```bash
python3.12 -m pip install --no-index --find-links=<bundle>/wheelhouse uv
```

**需要浏览器自动化（Playwright Chromium）**
离线包默认不含（约 150M）。在构建机上执行：
```bash
PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright \
  <构建机 python> -m playwright install chromium
# 摆渡 ~/.cache/ms-playwright 后，在目标机设置：
export PLAYWRIGHT_BROWSERS_PATH=/opt/ms-playwright
```
若目标机已有 Chrome/Chromium，可跳过。

**端口被占用**
`ss -ltnp | grep 8088` 查占用者；改用 `--port` 换端口，记得同步调整防火墙规则。

**页面 404**
前端产物缺失（旧包或构建中断），在构建机重新 `bash scripts/offline_pack.sh` 后重装。

## 9. 升级

数据在 `~/.octop/`，与程序分离，升级不丢数据：

```bash
# 构建机：拉取新代码后重新打包
git pull && bash scripts/offline_pack.sh

# 目标机：解压新包并重跑安装脚本（保留 --host 等参数）
tar -xzf octop-offline-aarch64-<新版本>.tar.gz
bash offline_install.sh --bundle ./octop-offline-aarch64-<新版本> --host 0.0.0.0
```

安装脚本会复用已有 venv 并**跳过初始化**（检测到 `octop.db` 即跳过），`config.json` 中已有的 `bind_host` 不会被重置，数据库结构在下次启动时自动迁移。升级前建议备份：

```bash
~/.octop/bin/octop backup
```

## 10. 附：手工流程（不使用脚本）

```bash
# 1. 建 venv（用离线解释器）
<bundle>/python/cpython-3.12.14-linux-aarch64-gnu/bin/python3.12 -m venv ~/.octop/venv

# 2. 装构建工具
~/.octop/venv/bin/python -m pip install --no-index \
  --find-links <bundle>/wheelhouse setuptools wheel

# 3. 离线安装 octop
~/.octop/venv/bin/python -m pip install --no-index \
  --find-links <bundle>/wheelhouse \
  --find-links <bundle>/dist \
  --no-build-isolation \
  <bundle>/dist/octop-1.0.2b4-py3-none-any.whl

# 4. 验证并启动（--host 0.0.0.0 供跨机访问）
~/.octop/venv/bin/octop --version
~/.octop/venv/bin/octop run --host 0.0.0.0 --port 8088
```
