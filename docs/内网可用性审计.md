# Octop 内网可用性审计

对 Octop 在**无外网 / 弱外网内网**环境下「哪些功能不可用、为什么、怎么预置」的系统性审计。

> **审计基线**：`1.0.2b4`（`origin/main` = `232030f4`）。
> 文中所有 `文件:行` 均基于该版本，版本升级后行号可能漂移，文件路径保持有效。
> **审计范围**：`src/octop/infra/` 平台代码 + `experts/library/`（18 个专家 / 32 个技能）+ `subagents/library/`（约 490 个角色定义）中的可执行依赖。
>
> 配套文档：
> - [`docs/内网离线部署.md`](./内网离线部署.md) —— 单机离线包打包与安装
> - [`docs/内网流水线部署.md`](./内网流水线部署.md) —— 内网 CI/CD 流水线

## 0. 摘要

### 0.1 四个系统性缺口

| # | 缺口 | 本质 | 影响面 | 可修性 |
|---|------|------|--------|--------|
| 1 | **解释器错位** | agent shell 的 `PATH` 不含 `~/.octop/venv/bin`，`python` 落到系统解释器 | 所有依赖 Python 的技能 | ✅ 部署层一行修复 |
| 2 | **技能级外部依赖** | 技能假设 pip/npm/系统二进制已就绪，而它们不在 Octop 依赖中 | 11 个专家 | ✅ 预置资源 |
| 3 | **平台功能隐性必需依赖** | 知识库/Browser/桌面/OCR 缺资源时**启动不报错**，功能才失败 | 6 类平台功能 | ✅ 部分有官方开关 |
| 4 | **代码层内网反模式** | 600s 安装超时、HF endpoint 覆盖失效、自更新忽略 pip 配置等 | 全局 | ⚠️ 需改代码 |

### 0.2 快速决策表

| 你想要的 | 内网能否实现 | 需要做什么 |
|---------|------------|-----------|
| Office 文档（Word/Excel/PPT/PDF） | ✅ 能 | 修 PATH + 预置 pip/npm/系统依赖（§5.1） |
| 知识库问答 | ✅ 能（**必须**） | 预置 ONNX embedding 模型（§5.1） |
| 浏览器 AI+ | ✅ 能 | 预置 Chromium 二进制（§5.1） |
| 远程桌面 | ⚠️ 勉强 | 预置 VNC/xfce4 + mss/pynput（§5.2） |
| 语音 | ✅ 默认可用 | 保持 `browser` 预设，无需外网 |
| 定时任务 / 多渠道推送 | ⚠️ 部分 | dashboard 本地可用；IM 渠道需公网 |
| 云资源运维（腾讯云等） | ❌ 不能 | 强依赖公网 API |
| 新闻热点 / 股票行情 | ❌ 不能 | 强依赖公网抓取 |
| 微信公众号发布 | ❌ 不能 | 强依赖微信 API |
| 技能市场 / 专家市场 | ❌ 不能 | 强依赖公网 Hub |

## 1. 根因分析

### 1.1 缺口 1：解释器错位

**机制**：Octop 的所有依赖（含 `python-pptx`、`python-docx`、`openpyxl`、`Pillow`、`pypdf`）都装在 `~/.octop/venv`，但 agent 执行 shell 时拿到的是系统解释器。

| 环节 | 证据 | 事实 |
|------|------|------|
| systemd unit 不设 PATH | `infra/setup/service.py:391-395` | 只注入 `HOME` / `OCTOP_HOME` / `OCTOP_SERVICE_MODE` |
| agent 环境不注入 PATH | `infra/agents/workspace/execute_env.py:85-90` | 只注入 `OCTOP_AGENT_ID` / `OCTOP_AUTH_DIR` / `OCTOP_HOME` / `OCTOP_SKILLS_DIR` |
| shell 直接继承进程环境 | `execute_env.py:137`（`inherit_env = True`） | PATH 原样传给 agent |
| 技能文档用裸解释器 | `office-automation/skills/pptx/SKILL.md:18,47` | `python -m markitdown ...` |

**结果**：agent 既看不见 venv 里已有的包，又会尝试联网安装缺失的包，形成「包没装 + 网络不通」的双重失败。

**已做对的参考实现**（可作为修复模板）：

- `agents/providers/...`：`stock-assistant/SOUL.md:238` 显式用 `~/.octop/venv/bin/python3`
- `tencentcloud-api/skills/tcapi/SKILL.md:54-71`：探测顺序 `Octop venv → 系统 PATH → 装进 venv`
- `meituan-living-assistant/skills/meituan-deals/scripts/run.js:82-104`：

```js
// 解析优先级：OCTOP_PYTHON → $OCTOP_HOME/venv/bin/python → /app/.venv/bin/python → PATH
```

### 1.2 缺口 2：技能级外部依赖

技能依赖由 SKILL.md 的「前置依赖」章节声明，**Octop 主程序不提供**，需要用户自行准备。内网下 `pip install` / `npm install -g` 均不可用。

### 1.3 缺口 3：平台功能隐性必需依赖

这些功能**启动时不报错**，只有真正使用时才失败：

| 功能 | 失败点 | 证据 |
|------|--------|------|
| 知识库 | 无 embedding 模型 → 启用即抛错 | `infra/knowledge/gate.py:120-121,138-144` |
| 浏览器 AI+ | 无 Chromium 二进制 → `/browser/env-status` 报 error | `infra/browser/setup.py:367-395` |
| 远程桌面 | 缺系统包 → `deps_missing` | `infra/desktop/setup.py:348-356,629-642` |
| 知识库 OCR | 缺 `rapidocr`/`onnxruntime`/`pymupdf` | `infra/knowledge/ocr.py:31-33,103-141` |

### 1.4 缺口 4：代码层内网反模式

| 问题 | 位置 | 影响 |
|------|------|------|
| 缺包时**阻塞 600s** 才失败 | `infra/utils/runtime_packages.py:27` `INSTALL_TIMEOUT_SEC = 600` | 用户感知为「卡死 10 分钟」 |
| HF endpoint 显式传参，`HF_ENDPOINT` 环境变量**无效** | `infra/agents/providers/onnx_download.py:25-26,290,435` | 无法指向内网 HF 镜像 |
| 自更新显式 `-i`，**忽略 pip.conf** | `infra/setup/self_update.py:426,444,769-770` | 内网配了 pip 源也不生效 |
| 运行时 pip 安装不带 index 参数 | `infra/utils/runtime_packages.py:122-150` | 依赖 `PIP_INDEX_URL`/pip.conf，未配则走公网 |
| Docker 安装源写死 | `infra/mobile/docker_install.py:32-41,270` | 无法改内网镜像 |
| ACME / 公网 IP 探测写死 | `infra/setup/tls/acme_issue.py:25-26`、`infra/setup/tls/preflight.py:24-34` | 只能改用手动证书 |
| 语音/媒体 `base_url` 强制公网 https（SSRF 守卫） | `infra/voice/adapters.py:89-91`、`api/routers/observability.py` 同类 | 内网自建 TTS/媒体服务**会被拒绝** |

## 5. 内网预置 Checklist

### 5.1 必须（否则核心功能不可用）

**Step 1 — 修正解释器 PATH**（见 §1.1，收益最大）

```bash
# 方式一（推荐）：写入 ~/.octop/env，重启服务生效
cat >> ~/.octop/env <<'EOF'
PATH=/home/<user>/.octop/venv/bin:/home/<user>/.npm-global/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
EOF
```

- [ ] `PATH` 必须**保留 `~/.npm-global/bin`**（否则 `wecom-cli`/`lark-cli` 检测失效）
- [ ] 不要写 `OCTOP_*` / `HOME` / `USER` 等受保护键（`env_file.py:140-141`）
- [ ] 兜底：systemd drop-in `/etc/systemd/system/octop.service.d/20-path.conf`
- [ ] 验证：`~/.octop/venv/bin/python -c "import pptx, docx, openpyxl, PIL, pypdf"`

**Step 2 — Office 技能依赖**

- [ ] pip（装进 venv）：`defusedxml`、`lxml`、`pdf2image`、`markitdown[pptx]`、`pandas`、`pdfplumber`、`reportlab`
- [ ] npm（全局）：`docx`、`pptxgenjs`（可选 `sharp`/`react-icons`）
- [ ] 系统：`LibreOffice`(soffice)、`pandoc`、`poppler-utils`、`qpdf`
- [ ] 系统：`gcc`（`soffice.py:87-99` 在 AF_UNIX 受限时现场编译 shim）
- [ ] 可选：`pypdfium2`、`numpy`、`pytesseract`、`pdftk`

**Step 3 — 知识库 embedding 模型**

- [ ] 放置至少 1 个 ONNX 模型到 `$OCTOP_HOME/embedding_models/`
- [ ] 设置 `OCTOP_ONNX_COS_BASE` 指向内网对象存储
- [ ] 验证：控制台 → 知识库 → 启用（无模型会直接报错）

**Step 4 — 浏览器 Chromium**

- [ ] 摆渡 `~/.cache/ms-playwright/chromium-*` 或预装系统 Chrome
- [ ] 设 `PLAYWRIGHT_BROWSERS_PATH` 指向缓存目录
- [ ] 验证：`GET /api/browser/env-status`

- [ ] 知识库 OCR：`rapidocr`、`onnxruntime`、`pymupdf`
